# Собственная аналитика Balady+ — бриф для DevOps

> Коротко: разворачиваем **свой** сервер продуктовой/технической аналитики
> (вместо мёртвого UXCam и внешних SDK, к которым потеряны доступы).
> Целевой стек — **PostHog self-hosted** (open source: свой UI, своя БД, API).
> Приложение уже готово слать события — не хватает только сервера.

## Зачем

- **Потеряны доступы** к легаси-системам (UXCam, Mixpanel, Insider, BytePlus) —
  данные утекают на чужие сервера, дашбордов у нас нет.
- Нужны свои данные: воронки поиска/навигации, экраны, ошибки API, тайминги —
  внутри нашего контура (data residency, PII под нашим контролем).
- Первый шаг сделан: UXCam удалён из приложения, все его ~200 событий
  переведены на внутренний фасад `BaladyAnalytics` (пока — no-op/лог).

## Что развернуть

**PostHog self-hosted** (https://posthog.com/docs/self-host):

- Вариант A (старт/пилот): `docker compose` на одной VM —
  4 vCPU / 16 GB RAM / 200 GB SSD достаточно для начала.
- Вариант B (прод): Helm-чарт в k8s. Внутри: ClickHouse (события),
  PostgreSQL (метаданные), Redis, MinIO/S3 (сессии, если включим).
- Домен вида `analytics.<наш-контур>` + TLS. Доступ к UI — по SSO/VPN команды.
- Бэкапы: ClickHouse + PostgreSQL, ретеншн событий — 12 мес (обсуждаемо).

## Какие запросы пойдут от приложения (и почему)

| Запрос | Что это | Объём (оценка) |
|---|---|---|
| `POST /batch` | батчи событий (JSON): экраны, тапы, поиск, ошибки API | основной поток; батчи по 10–50 событий, gzip |
| `POST /decide` | feature flags / конфиг SDK (опционально, фаза 2) | 1 на старт сессии |
| `GET /array/...` | конфиг JS/SDK (опционально) | редко, кэшируется |

События шлёт мобильное приложение (iOS/Android) от лица пользователя —
endpoint должен быть доступен из публичного интернета (как обычный API),
только POST, без CORS-послаблений сверх необходимого.

## Что нужно от приложения (уже заложено)

- `.env.<flavor>` → `BALADY_ANALYTICS_MODE` = `legacy` | `dual` | `ours` —
  рубильник (сейчас prod=`legacy`, остальные=`dual`).
- Когда сервер будет готов: добавим `BALADY_ANALYTICS_URL` + project API key
  PostHog в `.env` и заменим логирующий транспорт на PostHog SDK — код фич
  не меняется.

## План (фазы)

1. **Сейчас**: фасад в приложении, транспорт-заглушка. Ничего никуда не шлётся.
2. **Пилот**: PostHog на stg-контуре → `dual` на stg/dev сборках → проверяем
   дашборды (воронка поиска, screen views, APIError).
3. **Прод**: PostHog в проде → prod переводим в `dual` → миграция остальных
   легаси-потоков (Mixpanel-тайминги, Urbi Analytics) внутрь фасада.
4. **Финал**: `ours` — легаси-SDK отключаются по мере готовности.
   BSS (наш серверный поток для поиска/карты) живёт независимо и остаётся.

## Безопасность / PII

- Данные не покидают наш контур (в отличие от UXCam/Mixpanel/BytePlus).
- Identity: национальный ID использовать **нельзя** как distinct_id в открытую —
  на фазе «Пилот» согласуем хэширование (например, SHA-256 от `sub`).
- Маскирование: сессионные записи (replay) включать только после ревью PII.
